Evidence: `coverage_run_output.txt` (full run log). Per-file HTML/lcov report: repo-root `coverage/lcov-report/index.html` and `coverage/lcov.info` (generated by this same run, referenced not re-derived).

## Measurement method and scope
This repo's own coverage config (`vitest.coverage.config.ts`) deliberately scopes coverage measurement to `packages/*/src/**/*.ts`, tested via `packages/*/test/**/*.test.ts`, using the V8 coverage provider. The config's own header comment explains why: app-level suites (api-gateway, settlement-worker, etc.) are largely `describe.skipIf(!PG_UP)` against live Postgres/Redis, so including them would make the coverage number a function of whether infra happened to be running — the project's own CI avoids that by measuring integration coverage separately via `npm run test:e2e`. This pass respects that existing design rather than inventing a different measurement scope.
