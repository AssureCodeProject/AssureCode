# RETRACTED — "Adaptive Zero-Knowledge Multi-Agent Consensus Protocol (AZK-MACP)"

> **Status: withdrawn.** This document presented a research paper describing a
> protocol that was never implemented, supported by a benchmark table
> (§4, "Experimental Results & Performance Benchmarks") whose five figures were
> never measured. It has been withdrawn rather than deleted, so that the
> correction is part of the record.
>
> The prior text is recoverable from git history.

This is the second retraction in this repository. The first,
[`NEXTGEN_RESEARCH_PARADIGM.md`](./NEXTGEN_RESEARCH_PARADIGM.md), withdrew the
QR-NGC paper. Both documents were written before the system was measured, and
both reported results for mechanisms that did not exist.

---

## The results table

Every row of §4 was presented as an experimental measurement. No benchmark
produced any of them.

| Claimed metric | Claimed value | Status |
|---|---|---|
| Vector search latency | 4.2 ms HNSW vs 78.4 ms sequential scan — **18.6× faster** | **Withdrawn.** The HNSW index is real (`idx_rag_embeddings_hnsw`) and is genuinely queried by the scope guard, but no A/B latency measurement against a sequential scan was ever run. The speedup factor was invented. |
| Outbox relay latency | 3.8 ms via `LISTEN/NOTIFY` — **131.5× faster** | **Withdrawn.** There is no `pg_notify` trigger and no `notify_outbox_event()` function anywhere in `infra/migrations/`. `OutboxRelay` still polls on a timer. The mechanism does not exist, so the latency was not measured. |
| Ledger proof verification | $O(\log N)$ Merkle proof | **Partially real, but not as described.** An RFC 6962 Merkle tree with inclusion proofs was built in Phase 8, so $O(\log N)$ inclusion proofs do exist. It is a binary Certificate-Transparency tree, **not** a Sparse Merkle Tree, and the 1,000,000-state-transition figure was never run. |
| Scope creep detection | **100.0%** ($\Delta$RAG trajectory) vs 81.2% static regex | **Withdrawn.** Measured accuracy on 50 held-out contracts is **36%** — 100% precision at **20% recall**. The 81.2% regex baseline was also never measured. |
| AI inference memory | **22.4 MB** (ONNX INT8) vs 185 MB PyTorch | **Withdrawn.** There is no ONNX runtime in this repository and no quantized model. The embedder loads PyTorch `all-MiniLM-L6-v2` directly. Nothing was measured. |

## The protocol itself

| Claimed mechanism | Status |
|---|---|
| **Continuous game-theoretic payout** $\mathcal{F}_{\text{Oracle}}(\mathbf{x}) \in [0,1]$ replacing the binary gate | **Not implemented.** Settlement is a binary gate — `trustScore >= 85 && criticalVulns === 0`, defined once in `packages/oracle`. There is no continuous payout ratio. |
| **Adaptive signal weights** $w_i(t)$ updated from the freelancer's historical trust score | **Not implemented.** The trust weights are fixed constants (0.40 / 0.25 / 0.20 / 0.15) and do not vary per freelancer or over time. |
| **$\Delta$RAG temporal integral** $\mathbf{D}(T) = \int_0^T \max(0, \epsilon - \nabla\cos)\,dt$ | **Withdrawn as stated; superseded.** Cumulative drift *is* addressed, but by a CUSUM statistic plus a conformal test martingale — not this integral, which was never coded. That detector is implemented and tested but **not calibrated**: it returns HTTP 503 rather than substituting a default, and no false-alarm rate is claimed. |
| **Three-tier decision protocol** (Allowed / Soft Warning / Blocked + automated amendment proposal) | **Not implemented.** The scope guard returns a binary in-scope decision. There is no soft-warning tier and no automated scope-amendment proposal. |
| **Sparse Merkle Tree** state proofs | **Not implemented as an SMT.** See the results table — a binary RFC 6962 tree exists instead. |
| **3-Agent AI Jury** (Developer Advocate / Client Representative / Neutral Judge) with payout ratio $\alpha$ | **Not implemented.** There is no arbitration backend of any kind. The dispute drawer in the web UI states this on its face and sends nothing. |
| **`LISTEN/NOTIFY` outbox trigger** (§3.1) | **Not implemented.** Presented as an implementation blueprint; the SQL was never applied. |

## Why this was withdrawn rather than revised

The document is not a proposal that overreached in places — it is a results
paper for a protocol that does not exist. Three of its five headline numbers
describe components with no code behind them at all (`LISTEN/NOTIFY`, ONNX,
the AI jury), and the one metric that *can* be measured — scope creep detection
— was claimed at 100% when the measured value is 36%. There is no revision that
preserves the paper's structure and remains true.

## Where the real numbers are

Each is regenerated by a named command, and each reports its own weak results.

- `docs/benchmarks/BENCHMARK_REPORT.md` — contract flow and scope-guard accuracy
- `docs/benchmarks/MATCHMAKING_REPORT.md` — retrieval metrics and the weight ablation
- `docs/ASSURECODE_COMPLETE_TECHNICAL_SPECIFICATION.md` §11 — measured results and limitations

For the optimizations this document proposed but did not implement, see
[`RESEARCH_PERFORMANCE_ANALYSIS.md`](./RESEARCH_PERFORMANCE_ANALYSIS.md), which
covers the same ground honestly — as recommendations with projected impact
rather than as measurements.
